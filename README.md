# AI Small Business OS

[English](README.en.md) · [공개 데모](https://aismall.vercel.app) · [포트폴리오](docs/PORTFOLIO.md)

필라테스·요가·클래스처럼 예약 중심으로 운영하는 소규모 사업장을 위한 플랫폼이에요. 문의 → 예약 → 회차 → 출석 → 고객 관리를 연결하고, 반복 업무는 **AI가 제안하고 사람이 승인**하는 방식으로 발전시켜요.

여러 사업장에 제공하는 **멀티테넌트 SaaS**가 목표예요. 독립 조직·브랜드를 테넌트로, 그 아래 매장을 지점으로 구분해요. 한 계정이 여러 조직에 소속될 수 있지만 각 조직의 데이터와 권한은 분리해요.

## 현재 구현 범위

| 영역 | 현재 상태 |
| --- | --- |
| UX·화면 | 기존 데모 47개 + 로그인·조직·직원·예약 개발 화면 6개 |
| 공개 데모 | 샘플 데이터와 화면 내 상태로 동작. 실제 운영 데이터 저장·인증 없음 |
| 서버 기반 | PostgreSQL 스키마, 조직·지점 RLS, 서버 소속 검사, 지점 조회·이름 변경 서비스 |
| 개발 DB | Supabase 서울: 마이그레이션·앱 전용 역할·TLS·원격 격리 검사 완료 |
| 변경 안전성 | 예상 버전 검사, 트랜잭션, 지점 이름 변경 감사 기록 |
| 검증 | 임시 PostgreSQL의 제한된 실행 계정으로 격리·권한·실패·동시 수정 테스트 |
| 로그인·온보딩 | 서버 인증·내부 사용자 연결·첫 조직과 지점 생성 구현. 실제 계정 로그인·조직/지점 조회·로그아웃 차단 확인 |
| 직원 관리 | 이메일에 연결된 일회용 코드 초대·수락, 지점/역할 배정, 접근 회수·감사 구현 |
| 수동 예약 | 지점별 등록·확정·변경·취소, 검색·페이지 이동·출석/정정·정원·감사 구현 |
| 회원 신청 | 이메일 확인 계정-고객 연결, 본인 신청·철회·조회·확정 예약 변경/취소, 관리자 승인/거절·프로그램별 자동 확정·정원 검사 구현 |
| 아직 필요한 것 | 대기열, 알림·결제·AI 실행·운영 인프라 |

기존 공개 데모는 샘플 데이터를 유지해요. 새 `/login`·`/workspace`에는 Supabase 인증과 DB 기반 조직·지점 흐름을 구현했어요. [로그인 사용법·검증 범위](docs/AUTH_ONBOARDING.md)를 봐요. **현재 공개 배포는 실사용 SaaS가 아니에요.**

## 빠른 시작

Node.js 22.9 이상과 npm을 사용해요. 화면 데모 실행에는 DB가 필요하지 않아요.

```sh
npm ci
npm run dev
```

[localhost:3000](http://localhost:3000)에서 첫 화면과 전체 화면 목록을 볼 수 있어요.

```sh
npm run typecheck
npm run lint
npm test               # Docker 필요: 임시 PostgreSQL 생성 → 테스트 → 삭제
npm run build
```

DB 설정과 마이그레이션은 [개발 가이드](docs/DEVELOPMENT.md)를 따라요. `main` 푸시는 공개 배포로 이어지므로 커밋·푸시는 별도 요청이 있을 때만 해요.

## 기술과 구조

Next.js 16 App Router · React 19 · TypeScript · Tailwind CSS 4 · PostgreSQL 17 · node-postgres

```text
src/app/                  공개 데모와 관리자·회원 화면
src/components/           공통 UI·기능별 화면 구성
src/data/                 샘플 데이터 (운영 DB와 연결되지 않음)
src/server/auth/          검증된 세션 인터페이스
src/server/access/        조직 소속 확인·트랜잭션·RLS 컨텍스트
src/server/db/            제한된 실행 계정의 DB 연결 풀
src/server/services/      조직·지점·직원·예약 업무 서비스
db/migrations/            버전·체크섬으로 관리하는 SQL
scripts/                  마이그레이션·임시 DB 테스트 실행
tests/                    실제 DB 격리·권한 통합 테스트
docs/                     현황·설계·개발·운영 점검·기획 기록
```

두 실제 계정의 직원 초대·역할 변경·회수 검증을 완료했어요. 수동 예약의 검색·회차 변경·출석 기록/정정도 실제 DB와 관리자 화면에서 확인했어요. 회원 신청·승인 대기도 구현했고 실제 두 계정 흐름을 확인했어요. 회원 모바일 카드·하단 메뉴와 관리자 예약 목록·업무 탭에 기존 Figma 디자인 구성을 적용했어요. 회원·관리자 화면의 실제 계정 시각 검증과 관리자 검색·탭 이동을 확인했어요. 회원 직접 변경·취소도 24시간 전 마감과 함께 구현·검증했어요. 프로그램별 자동 확정과 실제 회원 신청도 검증했어요. 등록 요청 중복 방지와 지점 전체 선택 검색도 구현했어요. 다음은 알림 준비 → 알림·복구·구독 → 승인형 AI예요. 운영 배포는 아직 하지 않았어요.

직원 초대와 권한 변경 사용법·제한·검증 범위는 [직원 관리](docs/TEAM_MANAGEMENT.md)를 봐요. 초대 메일은 자동 발송하지 않아요.

예약 알림은 [알림 대기열 기반](docs/NOTIFICATION_OUTBOX.md)까지 구현했어요. 예약 변경과 알림 요청을 함께 저장하고 전용 워커 권한·재시도·만료 복구를 검증했으며, 실제 발송은 아직 연결하지 않았어요.

예약 관리의 **알림 현황** 탭에서 지점별 대기·처리 중·완료·최종 실패와 오류를 조회할 수 있어요. 최종 실패는 조건에 따라 최대 3회 수동 재처리할 수 있어요. 실제 발송은 아직 연결하지 않았어요.

회원은 내 정보에서 사업장별 예약 이메일 수신을 선택할 수 있어요(기본 꺼짐). 발송 대상·동의·연결 회수·최신 예약·인증 이메일 검증 기반을 추가했으며, 실제 발송은 아직 연결하지 않았어요.

운영 화면의 정보 배치·컴포넌트·검증 범위는 [워크스페이스 디자인](docs/WORKSPACE_DESIGN.md)에 정리했어요.

발송 워커와 Supabase 인증 조회·선택형 Resend adapter 코드를 구현했어요. 기본 비활성·허용 수신자 제한이며 실제 발송/스케줄은 연결하지 않았어요. [워커 실행 경계](docs/NOTIFICATION_OUTBOX.md)를 봐요.

관리자 알림 현황에서 최근 차단·재시도 사유를 확인해요. `npm run notifications:check`로 발송 없이 파일럿 설정 형식을 점검할 수 있어요. [준비 절차와 한계](docs/NOTIFICATION_OUTBOX.md)를 봐요.

파일럿 워커는 조직·지점을 필수 지정해요. `npm run notifications:check -- --scope-preview`로 해당 지점의 큐를 읽기 전용 확인할 수 있어요. 설정과 제한은 [알림 운영 문서](docs/NOTIFICATION_OUTBOX.md)를 봐요.

`npm run notifications:pilot`은 기본 읽기 전용 미리보기이며, 실제 실행은 명시적인 실행 옵션과 활성화 설정이 모두 필요해요. [파일럿 실행 절차](docs/NOTIFICATION_OUTBOX.md#파일럿-실행-명령)를 확인해 주세요.

전달·반송 webhook 수신 기반도 구현했어요(기본 비활성). 접수 ID와 전달 사실을 분리하고 서명·중복·도착 순서를 검증해요. 관리자 전달 결과 표시는 다음 단계예요.

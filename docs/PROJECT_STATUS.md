## 0. 새 세션 시작 체크리스트

1. **사용자에게는 한국어(짧은 해요체)로 답해요.** 영어로 새지 않게 주의해요.
2. `git status -sb`로 `main`과 `origin/main` 차이를 봐요. **커밋·푸시는 사용자가 요청할 때만**, `main` 푸시는 곧 공개 배포(https://aismall.vercel.app)예요. 작업은 브랜치에서 해요. 커밋·푸시를 요청받으면 작업 브랜치를 푸시하고 `main` 대상 PR도 함께 생성해요. 기존 열린 PR이 있으면 중복 생성하지 않고 제목·본문을 최신 범위로 갱신해요. PR에는 변경 내용·이유·사용자에게 달라지는 동작·검증 결과·남은 한계·DB/배포 영향을 한국어로 적어요. PR 병합과 `main` 직접 푸시는 별도 요청 때만 해요.
3. 오늘 날짜가 **Test A 일정(10/26~30) 이후**면, 진행했는지·결과가 있는지 먼저 물어봐요(3장 1번).
4. 코드를 바꿨으면 `npx tsc --noEmit && npm run lint && npm run build`로 확인하고, 화면은 프로덕션 빌드(`npx next start -p 3300`)로 스크린샷을 찍어 봐요(7장).
5. 화면·데이터를 바꾸면 Figma·manyfast·코드가 어긋나지 않게 맞추고, 화면을 더하면 `docs/reference/screens.md`와 첫 화면 목록·숫자를 같이 고쳐요.

## 1. 개요

예약 중심 소규모 사업자(1~5인, 필라테스·요가·원데이 클래스)를 위한 운영 플랫폼이에요. 문의·예약·회차·고객을 한곳에서 다루고, 반복 업무는 AI가 **제안**하고 사람이 **승인**해서 실행해요. 핵심은 자동화 자체가 아니라 "AI가 무엇을 하려는지 이해하고 통제할 수 있는 경험"이에요. 포트폴리오로 공개해요.

- **1차(지금)**: 리서치 → UX/UI → 디자인 시스템 → 프로토타입 → 퍼블리싱 — 내가 할 수 있는 건 끝났고, Test A와 전문가 검토만 남았어요.
- **2차**: 여러 사업장에 제공하는 멀티테넌트 SaaS로 확장(10/13 사용자 결정). DB·RLS·서버 소속 검사·지점 서비스 기반을 구현했어요. 로그인·내부 사용자 매핑·첫 조직/지점 생성까지 구현했고 실제 계정의 기본 흐름도 확인했어요. 직원 코드 초대·배정·회수도 구현했어요. 두 계정의 초대·역할 변경·회수 화면 검증도 완료했어요. 고객·프로그램·회차·수동 예약 확정/취소까지 구현했어요. 예약 검색·변경·출석 정정도 구현했어요. 관리자 확인형 회원 신청·승인 대기도 구현했어요. 회원 신청·승인 두 계정 흐름 검증도 완료했어요. 회원·관리자 예약 디자인 구성도 적용했어요. 신청 시트 제출까지 검증했어요. 프로그램별 자동 확정도 구현·회원 화면 검증했어요. 대기열·알림·AI는 남아 있어요.

## 6. 꼭 지키는 결정

자세한 근거는 `docs/reference/decisions-D01-D15.md`.

**역할**
- 최고관리자(브랜드 전체) → 중간관리자 = 사업장 오너·매니저(배정 지점). 직원은 실무자이고 관리 레벨이 아니에요(라우팅에서 지정해야만 승인 가능).
- 회원은 직접 신청·변경·취소해요. 고객은 가입 없이 공개 문의 페이지로 문의하는 비회원이에요.
- 지점이 1곳인 브랜드는 '대표(최고관리자·오너)' 한 사람이고, Team 모듈이 꺼져 있어요. 여러 지점 브랜드는 Team이 켜져 있어요.

**예약**
- 구조는 프로그램 → 회차 → 예약이에요. 정원은 1~N(1:1, 2인 듀엣, 6인 기구, 8인 그룹).
- 그룹은 자동 확정이고, 기구·듀엣·1:1은 관리자 확인 후 확정이에요(기구는 설정으로 자동 확정 가능).
- 대기 신청은 예약이 아니에요. 기본은 알림 후 선착순이에요.
  - '자리 나면 자동 확정'은 프로그램 설정과 회원 동의가 모두 있어야 해요(둘 다 기본 꺼짐).
  - 자동 확정은 수업 3시간 전까지만 되고, 확정 후 1시간 안에는 취소할 수 있어요.
- 변경·취소 마감은 수업 24시간 전이에요. 예외: 참석 확인에 '못 가요'로 답하면 마감이 지나도 수업 전까지 바로 취소되고 사유는 '참석 확인 응답'(F-HCFDIB·F-DMWGKQ, 예약·정원 정책). 시간이 지났다고 출석이 되는 건 아니에요(이용 결과는 예약 상태와 따로 기록).

**AI**
- 자동 실행은 위험 낮음만 돼요. 위험 중간은 항상 승인하고, 같은 회차·같은 유형은 묶음으로 승인해요. 위험 높음 이상도 항상 승인해요.
- AI의 예약 생성·변경·취소는 항상 승인 후 실행해요. Automation은 예약을 바꾸지 않아요. 가드레일은 끌 수 없어요.
- 승인함은 AI·Automation 제안 전용이에요. 회원 신청은 예약 목록의 '승인 대기' 탭에서 처리해요.
- AI 권한은 '브랜드 기본값 + 지점별로 좁히기만' 가능해요.

**표기**
- 화면에는 한국어 표시명만 써요: 오늘·문의함·승인함·일정·AI 관리·활동 기록·지켜보기 모드·응대 지침·참고 자료·할 일·오프보딩·시험 실행.
- 위험 배지는 위험 낮음/중간/높음/매우 높음이에요. 영어는 개발명으로만 써요.
- '이용권' 문구는 쓰지 않아요(v1에 결제·이용권 없음). 가입 승인 단계도 없어요.

**10/5 결정**
- 회원 AI 도우미는 유료 플랜에서만 제공해요.
- 'AI 관리'는 별도 메뉴로 두고, 권한 설정은 '설정 › AI 권한'에 둬요.
- 공개 문의 확인 링크는 30일 동안 유효하고, 다시 받기는 10분에 한 번이에요. 문의가 있었는지는 알려 주지 않아요.

**업종·용어**
- v1 업종은 미리 만든 회차의 정원이 1~N인 업종이에요. 용어는 브랜드 단위로 정해요(F-CGLLRZ).

## 7. 퍼블리싱 규칙(코드)

- **실행**: `npm run dev` · 확인은 `npx tsc --noEmit && npm run lint && npm run build`
- **토큰**: `src/app/globals.css`에 Figma 변수를 1:1로 옮겼어요. 색은 `bg-surface`, `text-fg-secondary`, `bg-risk-medium-bg`처럼 써요. 글자는 `text-h1`·`text-body-md`·`text-label-sm` 같은 유틸리티를 써요. 간격·반경은 Tailwind 기본 스케일과 같아요.
  - 다크 모드는 시스템을 따르고, `<html data-theme>`로 고정할 수 있어요.
- **컴포넌트**: `src/components/ui/`(배지·버튼·필터 칩·토글·회차 줄·브리핑 줄·결과 블록·승인 대기 줄)를 먼저 재사용해요. 클래스 합치기는 `cn()`(tailwind-merge, 텍스트 스타일 그룹 등록됨)으로 해요.
- **아이콘**: lucide-react를 써요(Figma 아이콘이 Lucide 스타일). 16px, 배지 안은 12px, 회원 하단 탭은 24px이에요.
- **데이터**: `src/data/`의 샘플을 써요. 회차 명단·관련 일·출석 기록은 `src/data/sessions.ts`예요. 기준 데이터에 이름이 없는 자리는 샘플 회원(박지민·최유나·오세린 등)으로 채웠어요. 10/14 11:00 1:1(이수연)은 출석으로 기록돼 있어서 오늘 '출석 확인 필요 1개 회차'와 맞아요. 회원 알림·안내 화면은 10/14 저녁(17:05) 시점의 시나리오이고, 김하늘님은 오늘 19:00 대기 2번에 '자리 나면 자동 확정' 동의함이에요. 기준일은 2026-10-14(수) 13:00, 재진필라테스 강남점, 사업장 오너 홍지수, 회원 김하늘이에요. 기준은 `docs/reference/canonical-data.md`이고, Figma가 옛 데이터면 코드는 기준 데이터를 따라요.
- **문구**: 짧은 해요체로 쓰고, 버튼에는 실제 행동을 써요("예약 만들고 메시지 보내기"). Primary 버튼은 한 화면에 하나예요.
- **배포**: Vercel이 GitHub 저장소와 연결돼 있어요. `main`에 올리면(push) https://aismall.vercel.app 가 자동으로 갱신되고, 다른 브랜치를 올리면 미리보기 주소가 생겨요. 그래서 `main` push는 곧 공개 배포예요 — 사용자가 요청할 때만 해요. Vercel CLI가 59로 오래됐어요(`npm i -g vercel@latest` 권장).
- **Next.js 16**: 새 API를 쓰기 전에 `node_modules/next/dist/docs/`를 확인해요. `params`·`searchParams`는 Promise예요.
- **화면 확인**: Chrome 창 크기를 바꿀 수 없을 때는 헤드리스 스크린샷을 써요. 헤드리스 창은 최소 폭이 약 500px이라, 모바일은 `--window-size=500,900`으로 찍고 가운데 430px을 봐요.
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --hide-scrollbars \
    --blink-settings=preferredColorScheme=1 --window-size=1440,1000 --screenshot=out.png http://localhost:3000/admin/today
  ```
- Figma에서 디자인을 가져올 때는 `figma-design-to-code` 스킬을 먼저 불러요. 그다음 `get_design_context`를 쓰고, 결과는 이 프로젝트의 토큰·컴포넌트로 바꿔 넣어요.

## 8. 도구 주의사항

- **manyfast**
  - 쓰기(`write_*`)는 '승인 대기'로 올라가요. 사용자가 결정한 내용이면 `review_items`·`review_prd`로 승인해요.
  - 정책은 섹션 24개까지만 저장돼요. 넘는 섹션은 소리 없이 빠지니, 넘으면 정책을 나눠요.
  - 와이어프레임 `insert`는 속성(옵션·체크·테두리)과 자식을 잃어요. 버튼 `variant`는 primary/secondary만 돼요.
  - 이미 있는 버튼의 연결 대상은 바꿀 수 없어요. 새 버튼을 넣고 옛 버튼을 지워요(insert는 label·variant·action은 지켜요).
  - 드롭다운 옵션은 어디서도 못 바꿔요 → 옵션 없는 드롭다운 + 라벨 괄호에 목록("예약 상태 (전체 / 승인 대기 / …)").
  - 웹 편집 모드는 글자 고치기·삭제·실행 취소뿐이고 속성 패널이 없어요. 선택한 요소 오른쪽 위 파란 점은 '삭제' 버튼이에요. 실행 취소로 되살린 요소는 속성(옵션 등)을 잃어요.
  - AI 작업(생성·플로우 적용)은 동시에 돌리면 잠겨요.
  - `plan_user_flow_edit`는 무료라서 노드 ID 확인용으로도 써요.
  - 비용: 화면 생성은 화면당 약 500, 플로우 이름 변경은 개당 약 30이에요.
  - **화면 재생성은 쓰지 않아요.** 일부만 고쳐 달라고 해도 화면 전체를 새로 만들고 숫자까지 바꿔요(10/6 Today 시험 → 버전 49로 되돌림). MCP 재생성은 예전 화면(n번호)의 페이지 UUID가 없어 쓸 수도 없어요.
  - 되돌리기는 `read_versions` → `restore_version`(사용자 확인 후). 자동 백업이 안 만들어질 수 있어요.

## 1. 개요

예약 중심 소규모 사업자(1~5인, 필라테스·요가·원데이 클래스)를 위한 운영 플랫폼이에요. 문의·예약·회차·고객을 한곳에서 다루고, 반복 업무는 AI가 **제안**하고 사람이 **승인**해서 실행해요. 핵심은 자동화 자체가 아니라 "AI가 무엇을 하려는지 이해하고 통제할 수 있는 경험"이에요. 포트폴리오로 공개해요.

- **1차(지금)**: 리서치 → UX/UI → 디자인 시스템 → 프로토타입 → 퍼블리싱 — 내가 할 수 있는 건 끝났고, Test A와 전문가 검토만 남았어요.
- **2차**: 여러 사업장에 제공하는 멀티테넌트 SaaS로 확장(10/13 사용자 결정). DB·RLS·서버 소속 검사·지점 서비스 기반을 구현했어요. 로그인·내부 사용자 매핑·첫 조직/지점 생성까지 구현했고 실제 계정의 기본 흐름도 확인했어요. 직원 코드 초대·배정·회수도 구현했어요. 두 계정의 초대·역할 변경·회수 화면 검증도 완료했어요. 예약·AI는 남아 있어요.

## 6. 꼭 지키는 결정

자세한 근거는 `docs/reference/decisions-D01-D15.md`.

**역할**
- 최고관리자(브랜드 전체) → 중간관리자 = 사업장 오너·매니저(배정 지점). 직원은 실무자이고 관리 레벨이 아니에요(라우팅에서 지정해야만 승인 가능).
- 회원은 직접 신청·변경·취소해요. 고객은 가입 없이 공개 문의 페이지로 문의하는 비회원이에요.
- 지점이 1곳인 브랜드는 '대표(최고관리자·오너)' 한 사람이고, Team 모듈이 꺼져 있어요. 여러 지점 브랜드는 Team이 켜져 있어요.

**예약**
- 구조는 프로그램 → 회차 → 예약이에요. 정원은 1~N(1:1, 2인 듀엣, 6인 기구, 8인 그룹).
- 그룹은 자동 확정이고, 기구·듀엣·1:1은 관리자 확인 후 확정이에요(기구는 설정으로 자동 확정 가능).
- 대기 신청은 예약이 아니에요. 기본은 알림 후 선착순이에요.
  - '자리 나면 자동 확정'은 프로그램 설정과 회원 동의가 모두 있어야 해요(둘 다 기본 꺼짐).
  - 자동 확정은 수업 3시간 전까지만 되고, 확정 후 1시간 안에는 취소할 수 있어요.
- 변경·취소 마감은 수업 24시간 전이에요. 예외: 참석 확인에 '못 가요'로 답하면 마감이 지나도 수업 전까지 바로 취소되고 사유는 '참석 확인 응답'(F-HCFDIB·F-DMWGKQ, 예약·정원 정책). 시간이 지났다고 출석이 되는 건 아니에요(이용 결과는 예약 상태와 따로 기록).

**AI**
- 자동 실행은 위험 낮음만 돼요. 위험 중간은 항상 승인하고, 같은 회차·같은 유형은 묶음으로 승인해요. 위험 높음 이상도 항상 승인해요.

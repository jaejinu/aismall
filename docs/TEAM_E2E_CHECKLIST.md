# 두 계정 직원 관리 검증

2026-10-14. [직원 관리 구현](TEAM_MANAGEMENT.md)

## 준비 상태

- 서울 `aismall-dev`에 0001~0003 적용 완료.
- 실제 최고관리자 계정: 조직·지점 조회와 직원 관리 화면 진입 확인 완료.
- 두 번째 직원 개발 계정: 생성 완료 확인. 관리자와 다른 이메일 계정이에요.
- 로컬 앱: `http://127.0.0.1:3300/login`. 서버가 종료됐으면 저장소 루트에서 `npm run start -- --hostname 127.0.0.1 -p 3300`으로 다시 실행해요.

Supabase 대시보드 계정과 앱 계정은 별개예요. 직원용 이메일은 관리자와 달라야 하고, 비밀번호는 사용자가 직접 입력해요. 직원 계정으로 새 조직을 만들지 않고 기존 조직 초대를 수락해요. 같은 브라우저 프로필의 탭은 쿠키를 공유하므로 탭만 나눠도 계정이 분리되는 것은 아니에요. 한 프로필에서는 로그아웃 후 계정을 전환하고, 동시에 확인하려면 별도 브라우저 프로필을 사용해요.

## 실행 순서와 기대 결과

| 순서 | 계정 | 행동 | 기대 결과 | 확인 상태 |
| --- | --- | --- | --- | --- |
| 1 | 관리자 | 직원 관리에서 직원 이메일·지점·직원 역할 확인 후 코드 생성 | 일회용 코드와 수락 대기 표시. 메일 자동 발송 없음 | 완료 |
| 2 | 직원 | 로그인 후 내 조직에서 코드 수락 | 초대 조직·배정 지점 조회 가능 | 완료 |
| 3 | 직원 | 직원 관리 URL 직접 접근 | 404, 직원 목록·초대 코드 노출 없음 | 완료 |
| 4 | 직원 | 같은 코드 다시 입력 | 거부, 소속 중복 생성 없음 | 완료 |
| 5 | 관리자 | 배정 변경 확인 후 매니저 역할로 변경 | 목록 갱신, 소속 버전과 감사 기록 증가 | 화면 저장·새로고침 확인 완료. 버전·감사는 DB 통합 테스트 근거 |
| 6 | 직원 | 조직·지점 재조회, 관리 URL 재접근 | 지점 조회 가능, 팀 관리 권한은 여전히 없음 | 완료 |
| 7 | 관리자 | 확인 체크 후 해당 직원의 조직 접근 권한 회수 | 권한 회수됨 표시, 관리자 자신의 접근 유지 | 완료 |
| 8 | 직원 | 기존 지점 URL 직접 재접근·새로고침 | 404, 조직 목록에서 회수된 조직 제외 | 완료 |

초대 발급·수락은 실제 개발 조직의 접근 권한을 생성해요. 브라우저 도구가 실행하는 권한 부여는 구체적인 대상 계정·조직·지점·역할을 확인한 뒤 진행해요. 생성된 초대 코드를 채팅·문서·스크린샷에 남기지 않아요. 화면 증거가 필요하면 코드가 사라진 목록 화면에서 확인해요.

지점이 하나뿐인 현재 개발 조직에서는 역할 변경을 화면에서 검증하고, 지점 간 이동은 두 지점 DB 통합 테스트 결과와 구분해 기록해요. 별도 요청 없이 실제 조직에 검증 지점을 추가하지 않아요. 회수한 소속의 복직은 현재 지원하지 않으므로 마지막 단계 뒤에는 직원 계정으로 해당 조직에 다시 들어갈 수 없어요. 테스트 이력은 삭제하지 않고 유지해요.

## 기존 증거와 이번에 남은 범위

38개 자동 테스트와 실제 개발 DB의 롤백 검증은 이미 통과했어요. 이번 목록은 실제 Auth 계정·쿠키·Server Action·브라우저 표시까지 연결되는지 확인하는 추가 검증이에요. 이를 완료해도 이메일 발송·회원가입·비밀번호 복구·토큰 만료 후 갱신까지 검증한 것은 아니에요.

실제 계정 이메일·비밀번호·초대 코드는 문서에 기록하지 않아요. 2026-10-14에 두 실제 계정으로 1~8의 브라우저 흐름을 완료했어요. 초대 수락·코드 재사용 거부·직원/매니저의 지점 조회와 팀 관리 404·매니저 배정 저장·조직 권한 회수·관리자 접근 유지까지 확인했어요. 회수된 직원으로 재로그인했을 때 조직 목록에서 기존 조직이 제외됐고, 기존 지점 URL과 팀 관리 URL이 모두 404였어요. 지점 URL은 새로고침 후에도 차단됐어요. 버전 증가·감사 기록·동시성은 위 DB 통합 테스트 근거이며 이번 화면에서 별도로 조회하지 않았어요.

회수된 직원 계정은 로그인 상태로 남아 있고 기존 조직 접근 권한은 회수된 상태예요. 새 조직이나 초대를 만들지 않았어요. 현재 조직이 없는 계정에는 ‘첫 사업장 만들기’가 표시돼요. 회수 이력이 있는 직원에게 접근 권한 없음·관리자 문의를 안내하는 별도 화면은 후속 개선 항목이에요. 로그인 상태에서 권한을 회수했을 때 다음 요청이 차단되는 동작은 DB 통합 테스트로 확인했으며, 이번 브라우저에서는 계정 전환 후 재로그인해 확인했어요.

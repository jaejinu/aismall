# 운영 워크스페이스 디자인

2026-10-16. 이번 작업은 기능 개발에 앞서 실제 운영 화면을 정리하는 단계예요. 완료 후 인증·발송 adapter와 워커 구현으로 돌아가요.

## 적용 범위

| 화면 | 구성 |
| --- | --- |
| 관리자 공통 셸 | 고정 사이드 메뉴, 현재 메뉴 강조, 경로 표시, 회원 화면 이동 |
| 예약 관리 | 지점/제목 → 검색 결과·승인 대기 요약 → 업무 탭 → 검색/목록 |
| 알림 현황 | 발송 준비 안내 → 상태별 카드 필터 → 목록/오류/재처리 → 페이지 이동 |
| 회원 내 정보 | 연결된 사업장·수신 상태 → 이메일 안내 → 수신 선택/저장 → 새 사업장 연결 |

기존 globals.css의 의미별 색상·타입 토큰과 Button, TeamForm을 사용해요. 업무 영역은 밝은 표면·얇은 테두리·16px 모서리로 묶고 검은색은 선택/주요 행동에 사용해요. 알림의 대기·처리 중·완료·실패는 텍스트와 아이콘을 함께 표시해요. 수치는 실제 반환된 데이터만 사용하며 예약 요약은 전체 건수가 아니라 ‘현재 검색 결과 · 페이지’예요.

모바일은 사이드 메뉴를 숨기고 업무 탭을 가로로 이동해요. 예약 행은 768px 미만에서 세로로 배치해 열이 겹치지 않게 해요. 회원 알림은 드롭다운 대신 두 라디오 영역으로 선택지를 바로 보여줘요. 기본 수신 거부, 서버 동의 버전 검사, 실발송 미연결 안내는 그대로 유지해요. 회원 연결이 없을 때는 연결 폼을 펼치고, 연결이 있으면 접어요.

## 코드 위치

- `src/components/workspace/booking-tabs.tsx`: 업무 탐색

- `src/components/bookings/booking-record.tsx`: 예약 행·관리 상세
- `src/components/bookings/notification-monitor.tsx`: 알림 상태·필터
- `src/components/workspace/member-notification-card.tsx`: 회원 수신 설정 카드
- `src/components/workspace/member-booking-view.tsx`: 회원 메뉴·설정 순서

## 검증과 범위

타입 검사·린트·Webpack 프로덕션 빌드를 통과했어요. 실제 관리자 계정으로 예약 목록과 알림 현황을 데스크톱 1440px·모바일 390px에서 확인하고 상태 카드 클릭 → 필터 반영·빈 결과를 검증했어요. 회원 카드는 실제 컴포넌트·프로덕션 CSS와 합성 데이터로 390px 선택·저장 안내를 확인했어요. 실제 회원의 수신 동의는 변경하지 않았어요.

이번 변경은 UI 중심으로 DB 마이그레이션·예약 데이터·실제 발송 경로를 바꾸지 않았어요. 기존 97개 DB/설정 테스트 통과 기록과 이번 UI 검증은 구분해요. 새 경로 추가 없음(53화면 유지). Figma 원본 파일 동기화와 실제 회원 계정 저장 검증은 별도로 남아 있어요. 커밋·푸시·공개 배포는 하지 않았어요.

## 알림 전달 결과 카드

각 알림의 최근 처리 결과 아래에 테두리 카드를 추가해요. 결과 라벨은 의미별 색과 텍스트를 함께 쓰고, 후속 안내·발생 시각·마지막 수신 시각을 표시해요. 다수 결과는 details로 펼쳐요. 모바일에서는 제목과 배지가 줄바꿈되도록 해요. 390px 합성 데이터 확인 완료, Figma 동기화는 아직이에요.

## 운영 화면 정보 밀도 정리 (10/16)

관리자 콘텐츠 최대 폭을 1280px로 제한하고 사이드 메뉴 폭을 조정했어요. 예약 검색은 이름/예약 상태/출석 상태를 먼저 두고 날짜 범위는 펼쳐서 사용해요. 날짜 조건이 이미 적용되어 있으면 자동으로 펼쳐져 숨은 조건이 생기지 않아요. 모바일 예약 행은 날짜 전체 폭 + 고객/프로그램 + 상태/출석의 두 열 구성이에요.

알림은 상태 요약 → 필터/목록 → 도움말 순서예요. 반복되던 접수 설명과 로그 카드를 줄이고 고객·예약 정보 바로 아래 전달 결과를 배치했어요. 차단/실패 안내는 계속 노출하며 시도 횟수·재처리 회차·원시 식별 정보는 ‘처리 이력·요청 정보’로 접었어요. 일반 도움말도 하단에서 펼쳐 확인해요. 주요 조작은 최소 44px 높이를 사용해요.

검증: 타입·린트·Webpack 빌드, 표시 정책 테스트 2개. 실제 관리자 예약 화면의 날짜 펼치기와 390px 행 배치, 합성 알림의 데스크톱/390px 표시·이력 펼치기·필터/빈 상태·조회 실패 시 이전 정보 제거를 확인했어요. 시스템 다크 테마를 유지했으며 이번 확인은 다크 화면 기준이에요. DB/권한/발송 로직 변경 없음. Figma 동기화와 회원 화면 전반의 시각적 마감은 아직 남아 있어요.

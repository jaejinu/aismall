# 직원 초대·배정·권한 회수

2026-10-14. [현재 아키텍처](ARCHITECTURE.md) · [로그인·온보딩](AUTH_ONBOARDING.md)

## 사용 방법

최고관리자가 로그인 → 내 조직 → 운영 지점 → **직원 초대·권한 관리**로 들어가요. 주소는 `/workspace/[tenantId]/team`이에요.

1. 직원 이메일·지점·역할(사업장 오너 / 매니저 / 직원)을 선택해 초대 코드를 만들어요.
2. 코드는 생성 직후에만 보여요. 관리자 본인이 직원에게 직접 전달해요. 현재 앱은 이메일을 보내지 않아요.
3. 직원은 초대받은 이메일의 확인된 앱 계정으로 로그인해요. ‘내 조직’의 **직원 초대 수락**에 코드를 입력해요. 현재 개발 계정은 Supabase Authentication에서 별도로 준비해야 해요.
4. 수락되면 배정된 지점에 접근할 수 있어요. 최고관리자는 직원 목록에서 지점·역할을 바꾸거나 조직 접근 권한을 회수할 수 있어요.

조직 최고관리자 생성·승격·이전·회수는 이 화면에서 지원하지 않아요. 일반 직원이 자신이나 다른 사람의 권한을 바꿀 수도 없어요.

## 현재 범위와 결정

- 첫 버전은 직원당 **활성 지점 한 곳**을 배정해요. 기존 여러 배정이 있더라도 변경 시 선택한 한 지점으로 모두 교체한다는 문구와 확인 체크를 표시해요. 다중 지점 체크박스 UI는 후속 범위예요.
- 초대 코드는 암호학적 난수 32바이트(256비트), 유효기간 7일, 한 번만 수락 가능해요. SHA-256 해시만 DB에 저장하고 원문은 URL·로그·감사 기록에 넣지 않아요. 분실하면 취소 후 다시 만들어요.
- 같은 조직·이메일의 대기 초대는 하나만 허용해요. 조직당 대기 초대는 최대 100개예요. 새 초대 시 만료된 대기 초대를 정리해요. 화면은 최근 초대 100개를 표시하며, 대규모 이력의 페이지 탐색·보관 정책은 후속 작업이에요.
- 초대 수락은 Auth 서버가 확인한 이메일로 비교해요. form/query/body의 이메일·user ID·role을 수락 근거로 쓰지 않아요. 인증된 이메일은 서버 `SessionProvider.verifiedEmail`로만 전달해요.
- 초대 발급자가 더 이상 활성 최고관리자가 아니거나 조직·지점·수락자가 정지 상태이면 수락을 거부해요. 사용·취소·만료 코드도 거부해요.
- 이미 해당 조직 소속 기록이 있는 계정은 초대로 기존 권한을 덮어쓰지 못해요. **회수된 계정의 재가입도 현재 지원하지 않아요.** 복직은 별도 승인·감사 흐름으로 추가해야 해요.
- 권한 회수는 해당 조직 소속과 모든 지점 배정을 비활성화해요. 다음 업무 요청부터 차단하며 다른 조직의 소속은 바꾸지 않아요. 이미 응답한 화면 데이터나 진행 중인 요청을 원격으로 지우는 기능은 아니에요.

## 코드·DB 경계

| 위치 | 역할 |
| --- | --- |
| `db/migrations/0003_staff_invitations.sql` | 비공개 초대 테이블, 소속 버전, 제한된 팀 관리 함수, 감사 유형 |
| `src/server/services/team.ts` | 입력 검증, 초대 코드 생성/해시, 인증·트랜잭션·만료 검사 |
| `src/server/auth/provider.ts` | 검증된 사용자에서 이메일 전달. JWT의 임의 이메일 필드로 대체하지 않음 |
| `src/app/workspace/team-actions.ts` | 인증 재검사, Server Action POST, 일반 오류·버전 충돌 메시지, 화면 갱신 |
| `src/app/workspace/[tenantId]/team/page.tsx` | 최고관리자 전용 직원·초대 관리 |
| `src/components/auth/team-form.tsx` | 처리 중 중복 클릭 차단, 성공·실패, 코드 일회 표시 |
| `tests/team.test.ts` | 실제 PostgreSQL의 권한·경합·만료·회수 검사 |
| `scripts/verify-hosted-team.mjs` | 실제 개발 풀러의 함수/RLS 검증, 끝에 전체 롤백 |

초대는 `app_private.staff_invitations`에 보관하며 PUBLIC·runtime의 직접 테이블 접근을 금지해요. SECURITY DEFINER 함수는 고정 `search_path=pg_catalog`, 스키마명을 명시한 정적 SQL, PUBLIC 실행 금지, 최소 함수 실행 권한을 사용해요. 내부 `require_team_admin`은 runtime도 직접 호출할 수 없어요.

서버·실행 DB 자격 증명은 계속 신뢰 경계예요. 함수의 actor와 verified_email 인수는 서버가 검증한 값만 전달해요. 임의 SQL 실행이나 서버 침해까지 이 구조가 막아주는 것은 아니에요. Data API에 함수를 노출하지 않아요.

관리 작업은 조직 행을 잠가 수락·취소·배정·회수를 직렬 처리해요. 배정·회수에는 소속 버전도 확인하므로 이전 화면으로 새 변경을 덮어쓰지 못해요. 조직 잠금은 초기 규모를 위한 선택이며 직원 수가 커지면 경합을 측정해야 해요. 팀 목록 조회도 같은 잠금을 사용하므로 장기 트랜잭션을 추가하지 않아요.

초대 발급·취소·수락·배정·회수는 각각 감사 기록과 한 트랜잭션으로 저장해요. 감사 실패나 세션 만료 시 업무 변경도 롤백해요. runtime이 관리용 감사 유형을 직접 추가할 수 없어요.

## 검증

- 설정 7개 + DB 통합 31개 = **38개 통과**. 팀 관리 8개 테스트 묶음에는 다른 조직·이메일 접근, 역할 상승, 초대 이중 수락, 취소/수락 경합, 만료·발급자 회수·조직/지점/사용자 정지, 배정 충돌, 감사 실패 롤백, 회수 후 접근 차단을 포함해요.
- 서울 개발 DB에 0003 적용 완료. `node scripts/verify-hosted-team.mjs PROJECT_REF`로 실제 제한 계정에서 초대→수락→배정→회수→RLS 차단·감사를 검증했어요. 한 트랜잭션에서 롤백하여 테스트 사용자·조직·초대를 남기지 않았어요. Auth 계정이나 이메일을 생성·발송하지 않아요.
- 타입·린트 확인, Webpack 프로덕션 빌드 성공. 기본 Turbopack은 기존 포트 생성 권한 오류가 계속돼요.
- 실제 최고관리자 계정으로 새 프로덕션 빌드의 조직 선택→직원 관리 진입, 지점 옵션·역할·구성원·초대 목록을 확인했어요.
- **두 실제 계정의 브라우저 초대 발급→수락→매니저 배정→회수 전체 흐름을 확인했어요.** 회수 후 직원 재로그인 시 조직 제외·기존 지점/팀 URL 404를 확인했어요. 로그인 유지 중 회수의 다음 요청 차단은 DB 통합 테스트 근거예요. 실제 계정의 만료 토큰 갱신도 별도 회귀 검증이 필요해요.
